冻结通过线结论：**未通过**。新版静默题 15/15（要求至少 14）；正常协作题 9/15（要求 15）；预算耗尽 5 次（要求 0），保护拒绝 1 次。

本轮测的是核心层 FIFO 模拟，使用真实包的工具说明、消息信封和保护逻辑；不是完整 Host 模型调度验收。这里只比较固定题，不推断所有实际对话的节省比例。

首批 [中断记录](../batch-g3j0uB/INTERRUPTED.json) 单独保留：缺少停止原因、预算估算重复，不能与本批拼接；其中一条被中断请求可能没有完整用量，首批记录不是完整账单。

原始逐 run 结果与 summary.json、analysis.json、manifest.json、harness-fingerprints.json 均在本目录。

具体未过线原因：

- E05 两版均 0/5。已用 token 未超过 12,000，但剩余额度不足以承担下一请求的输入与输出，因而预算预检查停止；保护拒绝为零。不能据此声称是新版独有回归。
- E06 新版 4/5。第 0 次中，B 的 17 与 C 的首次 29 都成功投递，A 已完成报告；A 过早催问引发 C 重发 29，第二次被正确去重。任务结果完成，但不满足冻结的零拒绝线。

独立只读复核确认上述分类。A 的确定性保护和 Web UI 验收通过，完整模型验收仍未通过；后续应继续解决任务等待、结果关联与结束语义，不能宣称当前版彻底消除了互聊。
