# dsh-widget

Page mode now has a separate type scale and responsive main/aside layout. Six task examples cover simulations, comparisons, walkthroughs, dashboards, exploration and explanatory pages; compact chat styling stays unchanged. See the [evaluation guide](eval/README.md) for the fixed DeepSeek Flash comparison and its limits.

Interactive cards in the dsh conversation, forked from [Nagi-ovo/dsh-visualize](https://github.com/Nagi-ovo/dsh-visualize) v0.1.7 (BSD 3-Clause, see [LICENSE.dsh-visualize](LICENSE.dsh-visualize) and [NOTICE](NOTICE)). Everything upstream ships is kept (the `visualize` tool and skill, streaming preview, sandbox and CSP, card styles, settings page, replay); this fork adds a host bridge inside each card frame: `window.dsh.widgetState` / `setWidgetState()` persist per-card state (≤ 16 KiB) under `<DSH_HOME>/widget/state/`, the `modelContent` part flows back to the model as an `<untrusted_widget_state>` system-prompt section (≤ 100 cards / 64 KiB), `sendFollowUpMessage()` sends a follow-up as the user after a gesture and a host-side confirmation dialog, and `openExternal()` opens http(s) links. Do not install it next to upstream dsh-visualize. See [README.zh.md](README.zh.md) for the full documentation (Chinese).

Experimental `dshViz.interaction({ form, fields, action, render })` provides native form capture and host-owned confirmation. Immutable input snapshots are appended to the same new user message as its intent; system rules stay fixed and prior messages are never rewritten. This requires revision 2 of the session-controller capture extension not present in stock dsh 0.2.1-rc.5 or 0.2.2-rc.1. The packaged [host support installer](host-support/README.md) verifies exact version/source fingerprints and prepares an isolated copy with doctor, activation, rollback and disable commands; no installed host is changed. Reviewed builds: dsh 0.2.1-rc.5 and 0.2.2-rc.1 (each support release is tied to the exact host version it was built from; rerun `install` after every dsh upgrade and replace the profile block printed by `dsh-widget-host profile-block`). Stock hosts show an unsupported message. See the [design and evaluation specification](docs/plans/2026-11-01-interaction-design.md) for the deployment dependency and fixed acceptance criteria.

The latest interaction candidate meets its fixed-case gate (10/12 end-to-end, 4/4 explicit, 4/4 negative). See the [acceptance report](docs/plans/2026-11-01-interaction-release-result.md) for retained failures, the reused baseline, and limits of the claim.
