# 交互回流发布补齐 · V2

用户授权补齐安装支持、完整模型对照和故障验收，并重新规划隔离评测预算。V1 失败及未运行记录保留，不覆盖，也不复用其成功样本作为 V2 成绩。V2 的范围与预算在首个 provider 请求之前冻结；执行结果另行登记。

## 固定题目与通过线

沿用 V1 的 8 道题、每组每题 2 次，交替基线/候选顺序，共 32 个 episode。只用 deepseek-flash，temperature 0.5、thinking disabled。不预载技能，不在题目提示 API，不编辑模型生成的 HTML，不自动重试生成。公开控件允许按语义人工辅助定位，须保留动作和证据。

候选正例端到端至少 10/12；显式 4/4、隐式至少 6/8；负例 4/4，算术不生成图 2/2；所有实际提交必须具有正确的同会话快照。基线低于 10 时候选至少多 2 个成功，否则不低于基线。接纳回执不等于模型收到了正确选择，更不等于续答满足全部条目。

机器规格：[cases-v2.json](../../eval/interaction/cases-v2.json)。每 episode 最多 8 次 provider 请求、10 次工具调用。每请求输入 24,000、输出 6,000 token；总上界 256 次请求、7,680,000 token、60 分钟。输入先估算，实际超限或用量不明立即停止整轮，不将超限归为已合规。该预算是最坏上界，不是预计消耗。

## 修正输入估算

从 DeepSeek 官方分发包取得 V4 tokenizer.json，只使用离线 tokenizers 加载词表，不执行远程模型代码。计数使用请求的语义文本及工具 JSON，剔除 HTTP JSON 转义膨胀；固定 framing 余量为 `256 + 16×消息数 + 4×工具数`，再乘 1.08 向上取整。

用 V1 的 54 次实际成功请求校准，估算/实际在 1.0157–1.0599；原 12 个预检拒绝请求的新估算均不超过 24,000，最高 21,825。校准不是未来请求的精确计数证明。代理保留每次估算、完整 provider usage；输入按 input + cache read + cache creation 汇总，输出使用最后的累积 usage，不重复累计流式 usage。缺少 message_stop、网络中断或未知用量不得计为成功。

## 安装与隔离

发布包增加 `dsh-widget-host`，为审阅过的 dsh 0.2.1-rc.5 创建独立支持副本。两个源文件的版本及 SHA-256 必须匹配。副本带输入捕获和队列退出保留；支持安装、doctor、切换、回滚和禁用。普通全局安装不修改；不把未知未来版本当兼容版本。

基线仍使用 V1 冻结的 baseline.tar.gz，不能以 Git HEAD 代替。候选使用 npm pack 产物。两组均使用相同安装支持层、独立 DSH_HOME、同一临时工作区与随机回环端口。禁用额外会话日志、插件清单与遥测上传。真实 DeepSeek key 只读取用户先前明确授权的配置项，复制至 0600 临时配置；宿主仅持代理占位值。3080/3091 与真实用户配置不改动。

## 必须补齐的确定性验收

- 安装幂等、版本/源文件不匹配拒绝、复制内容完整性、切换/回滚/禁用、激活中断可恢复。
- 延迟保存超过 1.5 秒后键盘捕获；预览固定 30，后续改 31 不影响提交。
- 提交前断网、刷新、核实不存在、以原 ID 和原快照重试，只产生一个输入。
- 接纳后丢失响应、刷新查回执，不重发。
- 保存失败可见，但本次捕获读取当前控件。
- Escape 取消不推理；切换会话不发送旧预览。
- fork 不继承父回执；新输入明确空快照，覆盖历史状态的歧义。
- page 聊天内折叠保留活动 frame；独立窗口无提交能力。
- 正常重启保留排队 A，之后普通输入读 B；已接纳 ID 重放无新增调用，私有哨兵不进入请求。

这些确定性检查使用测试 Adapter，不能替代真实模型对照。

## 执行版本修订（不覆盖旧结果）

V2 在工具层发现两个问题：流式 message_stop 早于 HTTP 流结束，代理持锁期间拒绝了正常的下一步；浏览器在外部脚本加载完成前操作控件。该轮 53 次请求、843,884 token 记作无效评测，消耗仍计入总预算。代理已用本地 TLS 流式假服务证明红测失败、修复后连续请求通过；浏览器改为等待 iframe load。

V3 使用同一冻结候选与基线，完整完成 32 个 episode：159 次请求、2,500,813 token。候选正例 5/12，显式1/4、隐式4/8；基线1/12；两组负例4/4。未过线原因包括读取参考过多导致请求/输入预算耗尽、render 参数误用、确认后扩大成项目搭建，以及一份声称90分钟但实际110分钟的议程。没有把接纳回执当作正确续答。原始结果见 `eval/interaction/results/2026-11-01-v3.json`。

V4 为新的候选代码版本，范围在 [V4 规格](2026-11-01-interaction-candidate-v4.md) 实施前固定。完整运行候选16个episode，比较V3完整冻结基线，不只补失败题；时间顺序不同于V3交替执行，报告会明确披露。每题8请求/10工具/24000输入/6000输出及所有质量通过线不变。新候选轮请求上限128，总token余额4,335,303；V2、V3、V4合计不得超过7,680,000 token，V2/V3记录和各自上限不修改。
