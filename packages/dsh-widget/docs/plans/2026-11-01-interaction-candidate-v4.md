# 候选 V4：减少生成误用和不必要上下文

实施前固定范围：只调整 skill 与图表参考的生成约定，不改变交互协议、模型、题目、动作、质量通过线或每题预算。V3 全部结果保留；V4 将完整运行候选 16 个 episode，不按失败题选择性补跑。比较组使用 V3 同一冻结基线的全部 16 个结果，明确披露时间顺序不同，不声称重新做了交替随机配对。消耗包含在已授权的本轮总预算内；若余量不足则记录未运行，不删除分母。

已观察的反例：

- 候选 V3 IC-E03 读取多份参考后，生成的图虽能提交，但后续请求估算超过冻结输入预算，无法完成续答。
- IC-E04 将 `render(values)` 当作单个 region 字符串使用，初始化抛错导致操作栏未注册。
- IC-E05 在小表单前额外探索目录、样式、模板与源码，用尽 8 次请求后无法续答。
- IC-E06 选择确认后转而规划创建 React 项目，偏离继续完善当前卡片的范围并用尽请求额度。

改动目标：

1. 表单、选择器及小型模拟优先直接使用技能中完整范式；第一张可用界面前最多读取一份匹配参考，不扫描插件源码或重复读取已注入样式。
2. 写清 `render` 始终接收字段对象；单字段绘图函数以 `values.region` 等显式适配。注册前自查默认字段的首次 render。
3. 图表参考本身足够完成标准曲线/柱图，不强制连锁读取大模板；保持原有主题、字体与动画要求。
4. action intent 保留原始任务事实、单位和范围；确认后基于公开快照完成原任务，小改动更新当前卡片，不擅自扩大成工程项目。不为示例旅行自定人数或把预算当报价。

验证：沿用 10/12 正例、4/4 显式、6/8 隐式、4/4 负例、2/2 算术及正确传参的固定通过线；全部 oracle 人工核对原始请求与回答。通过前不标记可发布。
