# 交互回流实施记录 · 2026-11-01

结论：实验实现已完成，包内检查与关键隔离链路通过；**发布门禁未通过**。正式 dsh 安装未改动，未 commit/push。

## 已实现

- `dshViz.interaction({ form, fields, action, render })`：原生表单字段声明、合法保存值恢复、本地联动、保存反馈及公开字段捕获。模型无需手写保存、拼追问或重试协议。
- 宿主操作栏：读取当前控件，展示固定快照，用户确认后在同一会话提交；后续编辑不改变已经预览的选择。回包核对 source、token、epoch、captureId；卸载与超时结束捕获。
- 输入接纳模块：输入与公开快照共同持久化，稳定 submissionId/inputId、内容冲突检查、去重和回执查询。普通输入同样捕获当时已保存的状态；privateContent 不进入该投影。
- 页面在聊天内收起、展开时保留活动 iframe；独立窗口继续只读。修复普通元数据刷新及鼠标/键盘模式变化误触发 iframe 重载的问题。
- 四个需要后续分析的模板接入新入口；纯本地排序演示不增加提交。技能主动识别选方案、调参数、填需求，资源按需读取，旧桥示例迁至独立 reference 并移除吞错示例。
- 提交结果不明时持久保留恢复 ID，刷新后先查询回执。状态读取失败显示重试，不以默认空状态挂载可写页面。

## 宿主依赖与隔离验证

已安装 dsh 0.2.1-rc.5 未提供 `sessionController.registerWidgetInputCapture`。`eval/interaction/prepare-host.mjs` 对该版本做精确形状检查，在临时副本加入输入捕获与持久 flush；插件只在能力存在时启用新操作栏。未支持的宿主显示不可提交，不静默退回文本追问。

进一步验收发现 `dsh-agent-loop` 生命周期退出默认取消未执行队列。原版的跨重启队列测试失败，已保留证据。`prepare-loop.mjs` 提出第二项最小宿主改动：生命周期释放调用 `cancel(..., { keepInbox: true })`，显式用户/归档取消路径保持原规则。临时副本复验通过：排队 A 后保存 B，重启后对应输入仍使用 A，下一条普通输入使用 B。

这两项都是**待正式上游接入的宿主改动提案**；没有修改系统 node_modules、真实 `~/.dsh`、3080 或 3091。它们不是已发布的正式 API。模型对照使用输入捕获副本；队列退出修复在模型对照结束后单独做确定性验证，不能说已被该模型对照覆盖。

## 验证范围

`npm run check`：类型检查、27 个测试文件 / 371 项测试、构建全部通过。

实际隔离宿主及 Chrome 验证了：

- 连续 32 次本地控件修改不新增模型调用。
- 预览 B/30 后改成 B/31，实际模型 Adapter 收到的正文仍是 B/30。
- 运行中排队 A、保存 B，队列执行使用 A，后续普通输入使用 B。
- 重放同一提交 ID 只产生一个输入，冷重启后原回执可查询；私有哨兵不在模型请求正文或捕获记录中。
- 加入临时 agent-loop 修复后，未执行的队列输入跨正常重启保留。
- 两组模型生成的排序页面均可推进到第一次插入后的 `[1,3,2]` 并重置到 `[3,1,2]`，没有暴露提交入口。

不能将这些检查写成 IC01–IC12 全部验收通过：慢保存跨手势窗口、真实网络断连前后分类、跨会话切换、fork/replay 生命周期与全部键盘路径仍需扩展浏览器故障验收。现有单测覆盖其中部分行为，不能代替这些真实故障场景。

**不具备回答质量比较结论。** 这版 driver 用 UTF-8 bytes/3 估算请求输入，偏保守；所有提交后的续答在转发前被估算预检拒绝。已经转发的请求实际最高输入仅 17,544 token；不能把预检拒绝写成「实际超过 24,000 token」，也不能把四个接纳回执写成「真实模型完整回流成功」。接纳层语义映射及 inputId 在机器报告中逐例保存。

初次配置预检发现 dsh 默认额外上传会话日志与插件清单，尚未发出模型请求时就被拒绝。两组随后一致禁用这两项诊断上传，保留零用量配置失败记录；工具目录、题目和模型参数没有改变。正式模型请求 temperature=0.5、thinking disabled、max_tokens=6000，usage 按 DeepSeek Anthropic 接口的 input + cache read + cache creation 汇总。

下一版评测首先需要修正输入预检方法并重新做总预算规划；当前原始失败保留，不在本轮放宽预算或补跑挑选成功样本。DeepSeek [官方 token 说明](https://api-docs.deepseek.com/quick_start/token_usage/)也说明估算与实际 usage 有差异；应记录两者，不能混称硬上限证明。

模型评测冻结候选的 manifest 与最终工作树存在一个明确差异：评测后增加了「状态读取失败不挂载可写 iframe」的防覆盖修复，该修复已红测→绿测并通过全包检查，但没有消耗额外预算重跑模型题。
